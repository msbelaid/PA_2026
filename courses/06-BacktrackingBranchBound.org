** What is backtracking?
#+BEGIN_EXPORT latex
\begin{block}{Backtracking}
Build a candidate \emph{one decision at a time}. As soon as a partial candidate breaks a constraint, abandon it, \emph{go back} to the last decision, and try the next choice.
\end{block}
#+END_EXPORT

#+ATTR_BEAMER: :overlay <+(1)->
- The same tree as brute force (course 04), but explored *partially*.
- Needs a test on *partial* candidates: can this beginning still lead to a solution?
- Exact: a cut branch contains no solution, so no solution is lost.
- Worst case: still exponential. In practice: often a tiny part of the tree.

#+BEGIN_EXPORT latex
\note{Brute force builds every complete candidate, then checks it. Backtracking checks as early as possible, on the partial candidate. The name comes from the movement in the tree: go down while the choices are valid, go back up (backtrack) when they are not. Many puzzles are solved this way by hand: Sudoku, a maze where we go back at each dead end. The quality of a backtracking algorithm depends on the test: the earlier it detects a dead end, the more of the tree it cuts.}
#+END_EXPORT

** The pattern: choose, explore, undo
#+begin_src java
void explore(Partial p) {
    if (p.isComplete()) {               // a leaf: a solution
        report(p);
        return;
    }
    for (Choice c : p.choices()) {
        if (!p.isValid(c)) continue;    // cut: this branch has no solution
        p.apply(c);                     // choose
        explore(p);                     // explore
        p.undo(c);                      // undo
    }
}
#+end_src

\pause
- The code of the subsets and the permutations (course 04), plus *one test*.
- To stop at the first solution: return a boolean, as =subsetSum= with =||=.

#+BEGIN_EXPORT latex
\note{Partial and Choice are not real Java classes here: they describe the shape of every backtracking algorithm. Three questions to answer for each problem: what is a decision (a level of the tree)? What are the choices at each level? What test tells that a partial candidate is hopeless? The undo step gives back to the shared state the value it had before the choice, as in the subsets of course 04. We now apply the pattern to the open question of the last course.}
#+END_EXPORT

*** Steps
    :PROPERTIES:
    :BEAMER_col: 0.36

#+BEGIN_EXPORT latex
\begin{itemize}
\item<2-> Row 0: try column 0.
\item<3-> Row 1: columns 0, 1 attacked; try 2. Row 2: no square.
\item<4-> Go back: row 1, column 3.
\item<5-> Row 3: no square. Go back to row 0.
\item<6-> Column 1: the queens fit at once.
\item<8-> 9 nodes, instead of $4^4 = 256$ candidates.
\end{itemize}

Row 2: column 0 same column, column 1 diagonal with row 1, column 2 same column as row 1, column 3 diagonal with row 1: no square, go back. Row 1, column 3. Row 2: column 1 is free. Row 3: every square is attacked: go back. Row 2 has no other free square, row 1 neither: go back to row 0, column 1. Then row 1, column 3; row 2, column 0; row 3, column 2: a solution. *** The rules
    :PROPERTIES:
    :BEAMER_col: 0.58
    :END:
Rows 0 and 1 are placed. Where can the queen of row 2 go?

#+ATTR_BEAMER: :overlay <2->
- *Same column* as a queen above: attacked (columns 1 and 3).
- *Same diagonal*: as many rows apart as columns apart (columns 2 and 4).
- *Same row*: impossible, one queen per row by construction.
- Only column 0 is safe. Checking one square: compare with each queen above, $O(n)$.

#+BEGIN_EXPORT latex
\note{Let students find the safe squares of row 2 before showing them. The queen of row 1 is in column 3: column 3 is attacked, and its two diagonals reach columns 2 and 4 one row below. The queen of row 0 is in column 1: column 1 is attacked; its diagonals reach columns 3 and, on the left, nothing in row 2 (column -1). Why the diagonal rule works: going along a diagonal, each step changes the row by 1 and the column by 1, so the two distances are equal. Choosing one queen per row removes the row constraint for free.}
#+END_EXPORT

** The algorithm
#+ATTR_BEAMER: :overlay <+(1)->
1. Start with row 0.
2. In the current row, try the columns from left to right.
3. A *safe* square: place the queen there, and go down to the next row.
4. Every row has a queen: a *solution*. Count it, or stop.
5. No safe square left in the row: remove the queen of the row above, and try its *next* column (go back).

#+ATTR_BEAMER: :overlay <+(1)->
- The pattern: *choose* a column, *explore* the rows below, *undo* the choice.
- 8 queens: 92 solutions. The first one found is the board of the first slide.

#+BEGIN_EXPORT latex
\note{Run the steps on the four queens tree of the previous slide: each step of the tree is one of these rules. Step 5 is the backtracking: when a row has no safe square, the mistake was made higher, so we go back one row and move its queen to the next safe column; if that row has no other column either, we go back again. To find all the solutions, after a solution we also go back (step 5) and continue. The search ends when the queen of row 0 has tried every column.}
#+END_EXPORT

** Constraint problems everywhere
#+ATTR_LATEX: :align lll
| Problem      | Decision                     | Test on the partial candidate             |
|--------------+------------------------------+-------------------------------------------|
| Sudoku       | the digit of an empty cell   | not already in its row, column or box     |
| Timetable    | the slot of an exam          | no student has two exams at the same time |
| Map coloring | the color of a region        | neighbours have different colors          |
| Maze         | the next corridor            | not a wall, not already visited           |
| Crossword    | the word of a slot           | fits the letters already placed           |

#+ATTR_BEAMER: :overlay <+(1)->
- The *order* of the decisions matters: start with the most constrained one.

#+BEGIN_EXPORT latex
\note{All these problems have the same shape: variables to fill, a few choices for each, and constraints between them. They are called constraint satisfaction problems. The order heuristic: fill first the cell of the Sudoku with the fewest possible digits; a dead end found high in the tree cuts a big subtree. Good solvers also propagate: after each choice, they remove the impossible choices of the other variables. Prolog, a programming language, has backtracking built in. Solvers for logic formulas (SAT solvers) handle millions of variables with the same idea.}
#+END_EXPORT

* Branch and bound

** From constraints to optimization
#+ATTR_LATEX: :align lll
|              | Backtracking                 | For an optimization problem       |
|--------------+------------------------------+-----------------------------------|
| Question     | is there a solution?         | which candidate is the *best*?    |
| Leaves       | solutions, or nothing        | many valid candidates, one best   |
| Cut a branch | it breaks a constraint       | ?                                 |

#+ATTR_BEAMER: :overlay <+(1)->
- Knapsack, delivery tour: almost every branch leads to valid candidates.
- Cut a branch when it *cannot beat* the best solution found so far.
- How do we know it cannot, without exploring it? An *estimate*.

#+BEGIN_EXPORT latex
\note{Back to the three problems of course 05. In the knapsack, every subset that fits is valid; in the tour, every order is valid. Backtracking only cuts the sacks that do not fit: not enough. Ask students: while exploring, we already have a tour of 25 km. We are building another tour, and the beginning is already 26 km. What should we do? Stop: it can only get longer. This is the idea, in its simplest form: compare a partial candidate with the best complete one found so far.}
#+END_EXPORT

** What is branch and bound?
#+BEGIN_EXPORT latex
\begin{block}{Branch and bound}
Explore the tree of partial candidates (\emph{branch}). For each node, compute a \emph{bound}: an optimistic estimate of the best candidate below it. If the bound is not better than the best solution found so far, cut the node.
\end{block}
#+END_EXPORT

#+ATTR_BEAMER: :overlay <+(1)->
- The bound must be *optimistic*: never worse than the truth, or the optimum may be cut.
- The best solution so far improves during the search: more and more cuts.
- A good first solution helps from the start: *greedy* (course 05).

#+BEGIN_EXPORT latex
\note{For a maximization (knapsack), the bound is an upper bound: the subtree cannot do better than it. For a minimization (tour), a lower bound: every tour of the subtree is at least that long. If the bound is too optimistic, the algorithm stays correct but cuts little; if it is not optimistic (it underestimates a knapsack subtree, for example), the algorithm can cut the optimal solution and becomes wrong. The algorithm is exact: it returns the best candidate, like brute force and dynamic programming. Greedy finds its place here: its solution is a good starting point for the best so far.}
#+END_EXPORT

** Knapsack: an optimistic bound
The sacks A, B, C of course 05, two new sacks D and E, a bag of 50 kg.

#+ATTR_LATEX: :align l|ccccc
| Sack (by value per kg) | D  | A  | B   | C   | E  |
|------------------------+----+----+-----+-----+----|
| Weight (kg)            | 10 | 10 | 20  | 30  | 10 |
| Value (1000 DA)        | 70 | 60 | 100 | 120 | 10 |
| Value per kg           | 7  | 6  | 5   | 4   | 1  |

#+ATTR_BEAMER: :overlay <+(1)->
- *Bound*: fill the room left greedily by value per kg, and *cut the last sack* into pieces.
- Root: D + A + B + $\frac{10}{30}$ of C $= 70 + 60 + 100 + 40 = 270$. No choice of whole sacks does better.
- First solution, greedy: D + A + B, C does not fit, then E: 240. The best: D + A + C $= 250$.

#+BEGIN_EXPORT latex
\note{When the sacks can be cut (flour, spices sold by weight), greedy by value per kg is optimal: this is the fractional knapsack. Cutting is a relaxation: we allow more than the real problem allows, so its best value is at least the real best value. Any relaxation gives an optimistic bound. This is the second use of greedy in this course: not to solve the problem, but to estimate it fast, in O(n) for the remaining sacks. The third use: the greedy choice (course 05) gives the first solution, 240, before the search starts. Let students find the best choice: D, A and C fill the 50 kg exactly, 250.}
#+END_EXPORT

Take D, A, B: 230 for 40 kg. Take C: 70 kg, too heavy, the backtracking cut. Skip C: the bound is 230 plus E, 240, not better than 240: cut, it is the greedy solution itself. Back to "take D, take A, skip B": the bound is 130 plus C entirely, 250, better than 240: explore. Take C: the bag is full with 250, the new best; nothing more fits, so it is a leaf. Skip C: the bound is 140, cut. Back to "take D, skip A": B and two thirds of C give 70 + 100 + 80 = 250, not better than 250: cut. Back to the root, skip D: A, B and two thirds of C give 240: cut. Ask students how many nodes this last cut saves: the whole "skip D" subtree, 31 nodes. The earlier the cut, the bigger the saving: with 40 sacks, a cut at the first level removes 2 to the power 40 nodes.}
#+END_EXPORT

** Delivery tour: a lower bound
The clients of course 05, and a new client D.

| W | 3 | 4 | 10 | 11 |
| A |   | 7 | 8  | 10 |

#+ATTR_BEAMER: :overlay <+(1)->
- The rest of the tour still *leaves* the current city and each unvisited client, once.
- Each time by a road *still usable*: to an unvisited client, or back to W.
- *Bound* = length so far + shortest usable road of the current city and of each unvisited client.
- Greedy: W A B D C W, 37 km. Root bound: $3 + 3 + 4 + 8 + 7 = 25$.

#+BEGIN_EXPORT latex
\note{The distances of course 05, with a fourth client D. A minimization: the bound is a lower bound, every tour below the node is at least that long. Why: from the current city, the van takes one road to an unvisited client, at least as long as the shortest such road; from each unvisited client, it leaves once, to another unvisited client or to W. At the root: leave W, 3 (to A); leave A, 3 (to W); B, 4; C, 8; D, 7. Example for the node "W, then A" (3 km): roads to A are no longer usable. Leave A to B, C or D: 7; B: 4 (to W); C: 10 (its 8 km road goes to A); D: 7. Total 3 + 7 + 4 + 10 + 7 = 31. Removing the roads that can no longer be taken makes the bound tighter as the tour grows. Greedy: A (3), B (7), D (7), C (10), back to W (10): 37 km.}

** Making branch and bound fast
#+ATTR_BEAMER: :overlay <+(1)->
- A *tighter bound*: more cuts, but more work per node.
- A *good first solution*: greedy, so that the cuts start at once.
- A good *order*: try the promising choice first (take the sack with the best value per kg, go to the nearest client).
- *Best first* instead of depth first: always expand the node with the best bound, from a priority queue (a heap).

#+BEGIN_EXPORT latex
\note{Each point is a trade-off. A perfect bound would be the true answer, and computing it is the problem itself; a weak bound is cheap but cuts little. Depth first uses little memory, the depth of the tree, and finds complete solutions fast; best first often visits fewer nodes, but keeps many open nodes in memory. The heap of course 00 gives the node with the best bound in O(log n). Branch and bound is the base of the industrial solvers for scheduling, transport and planning problems.}
#+END_EXPORT

* Summary

** Key takeaways
- *Backtracking*: build a candidate decision by decision; go back as soon as a constraint is broken. Choose, explore, undo.
- *Branch and bound*: for optimization problems; cut a node when its optimistic bound cannot beat the best solution found so far.
- Both are *exact*, and exponential in the worst case: the gain comes from the cuts, early in the tree.
- Greedy helps both: a first solution, an order of the choices, a bound (the fractional knapsack).

#+BEGIN_EXPORT latex
\note{Ask students what each algorithm of the course cuts, and why the cut is safe: subset sum, a negative target; queens, an attacked square; knapsack and tour, a bound that cannot beat the best. A cut is always a proof that a whole subtree contains nothing useful.}
#+END_EXPORT

** Backtracking or branch and bound?
#+ATTR_LATEX: :align lll
|          | Backtracking                       | Branch and bound                        |
|----------+------------------------------------+-----------------------------------------|
| Problem  | constraints: one or all solutions  | optimization: the best solution         |
| Cut when | the partial candidate breaks a rule | the bound is not better than the best  |
| Needs    | a test on partial candidates       | an optimistic bound, a first solution   |
| Examples | queens, Sudoku, timetables         | knapsack, delivery tour                 |

#+BEGIN_EXPORT latex
\note{Branch and bound is backtracking with one more kind of cut: in the knapsack, the sacks that do not fit are cut as in backtracking, and the hopeless branches are cut by the bound. Both explore the same tree as the brute force of course 04.}
#+END_EXPORT

** The delivery tour, four ways
#+ATTR_LATEX: :align lll :font \small
| Paradigm            | Cost                            | Optimal?                    |
|---------------------+---------------------------------+-----------------------------|
| Brute force         | $O(n!)$                         | yes, up to about 12 clients |
| Greedy              | $O(n^2)$                        | no: 30 km instead of 25     |
| Dynamic programming | $O(2^n n^2)$, memory $O(2^n n)$ | yes, up to about 25 clients |
| Branch and bound    | exponential, often much less    | yes, depends on the bound   |

#+BEGIN_EXPORT latex
\note{Four of the paradigms of course 04 on the same problem. The limits are orders of magnitude for one second or one minute of computation. Branch and bound has no simple formula: it depends on the instance and on the bound, from a few nodes to the whole tree. For 1000 clients nobody can guarantee the best tour in reasonable time with these simple methods; greedy gives a tour, typically 25 percent too long. The last paradigm of the table of course 04, stochastic algorithms, is the open question.}
